# Security policy

## Supported versions

Security reports are currently accepted for the latest code on the default branch. There are no tagged stable releases yet.

## Reporting a vulnerability

Please do not publish exploitable vulnerabilities, credentials, private data, or sensitive logs in a public issue.

Use GitHub's **Report a vulnerability** feature in the repository Security tab if private vulnerability reporting is enabled. If that feature is unavailable, contact the repository owner through the GitHub profile and request a private reporting channel.

Include:
- A concise description and potential impact.
- Affected commit, file, or version.
- Reproduction steps or a minimal proof of concept.
- Any suggested mitigation.

Please allow reasonable time for investigation and a coordinated fix before public disclosure.

## Scope and safety

Only test systems and data that you own or are explicitly authorized to assess. Do not upload production customer images, private datasets, secrets, or personal information to public issues.
